# token-digest

이 파일을 지금 읽은 것이 정상이다 — 트리거는 경로만 준다. **이 파일은 한 번만 읽고 다시 읽지 않는다.** 자기 지시를 `rg`·`grep`으로 찾지 않고, 개인 메모리(`~/.devin/`·`~/.codex/memories/`)도 읽지 않는다. 판단은 이 프롬프트와 아래 세 명령의 출력만으로 한다. 2026-09-17 실측으로, 다른 프롬프트에서 그 재읽기와 자기 검색이 회차 첫 두 턴을 먹었고 한 번은 13,250토큰에서 잘렸다.

하루치 루틴의 토큰 사용과 사고를 확인하고, **고칠 수 있는 것만 고치고 나머지는 제안으로 남긴다.** 산출물은 `handoff/token-findings.md` 한 파일이다.

## 권한 경계

직접 고쳐도 되는 것은 둘뿐이다.

- `bin/token-report.py` · `bin/token-breakdown.py` · `bin/token-incidents.py` — 관측 도구
- `handoff/token-findings.md` — 원장

**루틴이 실행하는 코드는 고치지 않는다** — `prompts/` 전부(이 파일 포함), `bin/round.py`, `bin/guarded.sh`, `bin/lock.sh`, `bin/pr-session.sh`, `bin/precheck.py`, `bin/az`, `state/` 전부. 여기서 개선점을 찾으면 findings에 제안으로 적고 끝낸다. 무인 세션이 루틴을 고치는 경로는 이미 사고를 냈다 — 2026-09-17 10:28에 들어간 변경으로 10:50 회차가 `bin/round.py: line 10: command not found`로 죽었다.

`git commit`·`git push`를 하지 않는다. 변경은 워킹트리에 둔다. `rm`을 쓰지 않는다 — 승인 프롬프트를 띄우고 무인 회차에는 답할 사람이 없다. 락(`lock.sh`)을 잡지 않는다 — 이 세션은 `state/`도 ADO·Slack도 건드리지 않아 다른 회차와 겹칠 자리가 없다.

## 1. 수치를 받는다 (한 턴)

오늘 날짜를 `YYYY-MM-DD`로 넣어 한 명령으로 돌린다. 세 스크립트가 각각 구간을 받는다.

```
python3 bin/token-report.py "<오늘> 00:00" && \
python3 bin/token-breakdown.py "<오늘> 00:00" && \
python3 bin/token-incidents.py "<오늘> 00:00"
```

전일 대비가 필요하면 같은 명령을 어제 구간으로 한 번 더 돌린다. **그 두 번이 이 회차가 도구를 부르는 기본 횟수다.** 세션 jsonl을 직접 훑지 않는다 — 스크립트가 이미 훑는다.

읽는 법은 이렇다.

- `token-report.py` — 주체별 총량. `사람 claude`가 크면 관측·작업 세션이 루틴보다 비싸다는 뜻이다. 2026-09-17에 그 값이 전체의 45%였다.
- `token-breakdown.py` — 회차 입력이 어느 도구호출에 붙는지. **비중 상위 두 줄이 그날의 절감처다.** 호출 수가 곧 턴 수다.
- `token-incidents.py` — 회차 목록·실패 신호·한도. 턴이 한 자리인 회차는 죽은 회차다. 실패 신호 건수는 **하한**이다(출력이 잘리면 안 잡힌다) — 0이 아니면 그 자체로 신호다.

## 2. 사고를 가른다

실패 신호나 죽은 회차가 있으면 **원인을 그날의 커밋과 대조한다.**

```
git log --since="<오늘> 00:00" --format='%h %ad %s' --date=format:'%m-%d %H:%M'
```

커밋 시각보다 뒤에 처음 나타난 실패는 그 커밋을 의심한다. 회차 세션을 열어 확인해야 하면 실패한 회차 **하나만** 연다 — 전부 열면 이 회차가 관측 대상보다 비싸진다.

한도 거절이 `워커`에 잡히면 그 구간의 수치는 **오염 구간**이다. 거절된 요청을 오케스트레이터가 기다린 값이 폴링에 그대로 실리므로, 절감 판정에 쓰지 말고 구간을 잘라 따로 적는다.

## 3. 고친다

관측 도구의 결함만 고친다. 결함의 기준은 **수치가 틀리게 나오는 것**이다 — 구간 귀속, 역할 분류, 분류 누락, 이중 계산. 출력 모양이 마음에 안 드는 것은 결함이 아니다.

고친 뒤 같은 구간으로 다시 돌려 값이 바뀌는지 확인하고, 바뀌었으면 findings에 옛 값과 새 값을 같이 적는다.

`token-breakdown.py`의 `RULES`에 `기타` 비중이 10%를 넘으면 분류가 낡은 것이다. 그 구간의 `기타` 호출을 몇 개만 꺼내 보고 규칙을 더한다.

## 4. 원장에 쌓는다

`handoff/token-findings.md` 끝에 그날 항목을 덧붙인다. 지우거나 다시 쓰지 않는다 — 누적 문서다. 항목 하나의 형식은 이렇다.

```
## <제목>
관측: <언제, 무엇을, 몇 건의 표본으로>
현재: <턴 수·토큰>
제안: <무엇을 어디로 옮기면 몇 턴이 주는지>
위험: <그 변경이 깰 수 있는 것>
```

규칙 넷.

- **표본 수를 항상 같이 적는다.** 표본 3개로 결론을 내지 않는다.
- **캐시 10% 환산을 쓰지 않는다.** 요금표를 확인한 적이 없다. 입력합·정가·턴만 쓴다.
- **관측되지 않은 실패에 기제를 제안하지 않는다.** 이 작업에서 그 이유로 제거된 기제가 아홉이다.
- 어제와 같은 결론이면 새 항목을 만들지 말고 **표본만 보탠다**.

변화가 없고 사고도 없으면 항목을 만들지 않는다. 그날은 "변화 없음"으로 끝내는 것이 맞다.

## 5. 보고한다

마지막 메시지에 이 넷을 적는다. 그 이상 쓰지 않는다.

- 오늘 총량과 전일 대비
- 사고 건수와 원인(모르면 모른다고)
- 직접 고친 것
- 사람이 반영해야 할 제안과 그 근거 수치
