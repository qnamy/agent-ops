# agent-teams.md — Agent Teams 사용법 (Claude Code 전용, 한국어 미러)

> 전역 CLAUDE.md에서 트리거 시 읽는다. Agent Teams는 **실험적** Claude Code 기능(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`)이며 인터랙티브 세션 전용이다 — 헤드리스 `-p`는 플래그가 켜져 있어도 조용히 일반 서브에이전트로 폴백한다. Codex에서는 사용 불가. 아래 사실관계는 Claude Code 2.1.245(2026-08) 기준 공식 문서를 따른다; 메이저 CLI 업그레이드 시 재검증할 것.

## 활성화

차단급 E2E 체크 두 건이 2026-08-26에 통과했고(① 플러그인 훅이 팀원 세션에서 발화, ② 플래그가 켜진 상태에서도 이름 없는 디스패치가 일반 서브에이전트로 유지), 플래그는 `~/.claude/settings.json` `env`로 승격됐다 — 모든 대화형 세션에서 팀을 쓸 수 있다. harnie의 팀 경로는 `instructions/team-collab.md`가 dev 파이프라인에 배선(자체 릴리스)되기 전까지 비활성이다.

## 라우팅: 직접 실행 vs 서브에이전트 vs 팀

결정 순서 — 먼저 맞는 것을 채택:

1. 헤드리스 세션이거나 플래그가 꺼져 있으면 → 팀을 절대 구성하지 않는다.
2. 소규모·순차적·동일 파일 위주 작업 → 직접 실행 또는 단일 서브에이전트(공식 가이드: 팀은 토큰·조정 비용이 상당히 더 든다).
3. 결과만 중요한 단일 작업(탐색, 단독 설계, 단독 리뷰) → **이름 없는 서브에이전트**.
4. 아래 5개 중 **3개 이상**이 "예"일 때만 팀을 구성한다: 멤버 간 직접 정보 교환이 필요하다 / 멤버들이 서로의 가설이나 설계에 반박해야 한다 / 공유 작업 목록과 자율 조정이 필요하다 / 여러 독립 도메인을 동시에 맞춰야 한다 / 기대되는 품질-속도 이득이 토큰+조정 비용을 넘어선다.

작업 도중 협업이 필요하다고 판단한 서브에이전트는 팀을 구성하지 **않는다**(중첩 팀은 미지원); 대신 `NEEDS-COLLAB: <이유>`와 부분 산출물 경로를 반환하고, 최상위 세션이 그 부분 산출물을 사전 작업으로 삼아 해당 단계를 팀으로 재실행한다.

## 강제 규칙

1. **일반 서브에이전트를 디스패치할 때는 절대 `name`을 넘기지 않는다.** 플래그가 켜진 세션에서 이름 있는 스폰은 조용히 다른 반환 계약을 가진 팀원이 되어버린다. 이 규칙은 팀 작업이 아닐 때도 항상 적용된다.
2. **팀당 산출물 소유자는 하나.** 단일 출력 파일은 정확히 한 팀원만 쓰고, 나머지는 읽기 전용 기여자다. 팀 단계에서 소스코드 쓰기는 없다.
3. **완료는 두 조건을 모두 갖춰야 한다**: 산출물이 디스크에 존재하고 리드가 읽어 확인함 ∧ 소유자의 결과 메시지를 수신. idle 알림만으로는 절대 완료가 아니다 — 페이로드는 `type/from/timestamp/idleReason` 4개 필드뿐이고 산출물이 없으며, `idleReason: "available"`은 "끝냈다"가 아니라 "놀고 있다"는 뜻이다.
4. **독립 리뷰어는 프로덕션 팀에 절대 합류하지 않는다.** 팀 내 "챌린저/악마의 대변인"은 리뷰어가 아니라 탐색자 역할이다. 팀 산출물이 정식 리뷰 루프(예: harnie의 크로스모델 루프)로 들어갈 때는 그 루프를 생략 없이 그대로 거친다 — 팀 내부 토론은 동일 프로바이더이며 그 무엇도 대체하지 않는다.
5. **팀 상태는 일회성이다.** 팀원은 `/resume`으로 살아남지 않는다; 복구는 디스크상의 산출물로부터 해당 단계를 재시작하거나, 부분 산출물을 이어받는 단일 서브에이전트로 격하하는 방식이다.
6. **팀원은 권한 상태를 절대 건드리지 않는다** (예: harnie `.harnie/` CLI, 원장, 승인 플로우).
7. **상한과 스폰 위생**: 팀당 팀원 ≤4명, 팀 단계당 산출물 1개. 스폰 시 각 팀원의 모델을 항상 명시한다 — 미지정 팀원은 리드의 모델을 상속하며 이는 대개 잘못된 선택이다. 추론 노력(reasoning effort)은 팀원별로 설정할 수 없다(리드에서 상속); 능력 배분은 모델 선택으로만 한다.

## 팀원 = 세 축

프로세스 역할(탐색자/설계자/빌더/리뷰어 — 팀에서는 리뷰어 금지) × 도메인 프로필(스폰 프롬프트로 주입, 새 에이전트 정의는 만들지 않음) × 모델 티어:

| 티어 | Claude | GPT (Codex) | 용도 |
|---|---|---|---|
| T4 | fable | sol + high effort | 되돌릴 수 없는 아키텍처 결정, 모호한 인시던트 분석 |
| T3 | opus | sol | 복잡한 설계, 리뷰, 보안, 데이터 무결성 |
| T2 | sonnet | terra | 표준 설계, 구현, 리뷰 |
| T1 | haiku | luna | 탐색, 분류, 좁은 범위 검증 |

harnie 내부에서는 `instructions/model-matrix.md`가 정본이며 이 표를 대체한다; harnie 밖에서는 `delegation.md` 티어를 따른다.

## 템플릿 (그대로 쓰지 말고 조정해서 사용; 고정 조직도를 늘리지 말 것)

- **T-A 다도메인 계약 설계**: policy-analyst(탐색자 × 정책 × T2) + lead-designer, 산출물 소유자(설계자 × 백엔드 × T3–T4) + frontend-designer(설계자 × 프런트엔드 × T2) + challenger(탐색자 × QA/신뢰성 × T3). 산출물: 설계 초안 1건 → 정식 리뷰 루프. 해당 리스크가 있을 때만 보안/마이그레이션/성능 탐색자(T3)를 추가한다.
- **T-B 경쟁 가설 인시던트 분석**: hypothesis-1..N(탐색자 × 가설 1개씩 × T2, N≤3) + refuter(탐색자 × 반박 × T3) + incident-writer, 산출물 소유자(설계자 × 종합 × T3). 산출물: 인시던트 리포트 1건.

## 사고 렌즈 (스폰 프롬프트 템플릿 전용)

재사용 가능한 탐색자 렌즈로, 스폰 프롬프트로 주입한다 — 새 에이전트 정의는 절대 만들지 않는다(harnie 내부에서는 read-only `harnie-scout` 정의에 얹는다):

- `skeptic-challenger` — 초안의 가정을 공격하고, 실패 모드와 반례를 사냥한다.
- `simplicity-advocate` — 요구를 충족하는 최소 설계를 주장하고, 과설계를 지적한다.
- `ops-risk` — 운영성을 파고든다: 장애 복구, 모니터링, 마이그레이션·롤아웃 리스크.

팀당 렌즈는 최대 1~2개, 팀 구성이 이미 정당화된 경우에만 추가한다. 렌즈는 논증만 하고 verdict를 내리지 않으며, 렌즈 토론은 어떤 리뷰 라운드도 대체하지 않는다(강제 규칙 4). 렌즈를 실제 에이전트 정의로 승격하는 것은 ~3회 실사용으로 가치가 입증된 후에만 한다(rule of three).

## 알려진 제약 (공식 문서 + 2026-08 E2E 기준 — 이를 감안해 설계할 것)

중첩 팀 불가; 세션당 팀 1개; `/resume`은 인프로세스 팀원을 복원하지 않음; 인프로세스 팀원은 백그라운드 서브에이전트를 스폰할 수 없음; 팀원 메시지와 idle 알림은 리드의 턴 경계에서만 전달됨 — 턴 도중의 리드는 아무것도 받지 못하며(결과가 필요하면 디스크에서 산출물을 직접 읽을 것) 팀원 쪽에서도 전달 여부를 확인할 수 없음; 공유 작업 목록 도구는 리드·팀원 어느 쪽에서도 관측되지 않음(2026-08 E2E); 세션 도중 변경한 훅 설정은 즉시 적용되지 않으며 재시작 없이 나중에 잡힐 수도 있음(재로드 트리거 미확인, 2026-08 E2E) — 방금 바꾼 훅이 걸려 있다고 가정하지 말고 발화로 실측할 것; 서브에이전트 정의를 참조하는 팀원은 그 `tools:`와 `model:`은 적용하지만 `skills:`와 `mcpServers:`는 적용하지 **않음**.
